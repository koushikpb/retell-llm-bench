# retell-llm-bench — design spec
Last updated: 2026-09-19 · Approved idea: `companies/retell-ai/ideas.md` §1 · Brief: `companies/retell-ai/build-brief.md` · Protocol source: `docs/api-notes.md` (the only protocol source)

## Goal
An offline CLI that plays the Retell side of the custom-LLM WebSocket protocol against any local server, runs a YAML scenario suite, and prints a results table, so a custom-LLM server can be tested without a live call (the gap named at api-notes.md:6).

## What ships
1. `npm run bench`: connects to `ws://127.0.0.1:3217/llm-websocket/<call_id>` (api-notes.md:14, 22), plays every scenario in `scenarios/`, prints the table, optionally writes JSON (`--json`).
2. Nine YAML scenarios (brief asks for at least 8, build-brief.md:31).
3. A scripted fake server (`npm run fake`, port 3218) for tests and the no-key smoke run (`npm run smoke` → `docs/smoke.txt`).
4. A Claude reference server (`npm run server`, port 3217) with two tools that carry a `message` parameter, idempotent booking, stale-response abort, `content_complete: true` in `finally`, `tool_call_invocation`/`tool_call_result` frames, keepalive echo (api-notes.md:93-100, 105). Runs only with `ANTHROPIC_API_KEY`; no test needs it.
5. `docs/results.md` generated by `npm run results` (`scripts/results.ts` starts the reference server in-process on a free port, runs 3 runs per scenario, writes the JSON and the markdown, stops the server, then prints `results run complete` as the guaranteed last log line, so the README's three commands work in one terminal and the build's success check is deterministic), README with that table, `docs/demo.gif` (fallback: `docs/smoke.txt`).

## Architecture and data flow
- **Protocol layer** (`src/protocol/schemas.ts`): zod schemas for every frame in api-notes.md §4 (Retell→server, discriminated on `interaction_type`) and §5/§7 (server→Retell, discriminated on `response_type`). `validateServerFrame(raw)` returns `{ frame | null, violations[] }`. It mirrors Retell's documented behavior: a frame with no `response_type` is parsed as a `response` and flagged (`missing_response_type`, api-notes.md:10, 104); a `response` with wrong field types is dropped and flagged (`schema`, api-notes.md:50); `end_call`/`transfer_number`/`digit_to_press` set together on a `response` is flagged (`exclusive_actions`, api-notes.md:51); a binary frame is flagged (api-notes.md:15). `agent_interrupt`, `update_agent` and `metadata` are accepted by `response_type` alone (the bench never emits or scores them; see Not doing).
- **Bench client** (`src/bench/client.ts`, `types.ts`): the Retell side of one call. Sends `update_only`, `response_required`, `reminder_required`, `call_details` (when the server's `config.call_details` is true), `ping_pong` every 2 s when `config.auto_reconnect` is true and expects a reply within 5 s (api-notes.md:23, 33, 44); any server `ping_pong` with an integer `timestamp` credits the oldest outstanding ping (the guide's code echoes the timestamp, but only "a ping_pong event back every 2s" is documented as required, so the field is validated, not matched). Records every received frame with `performance.now()`, keeps a `TurnRecord` per requested `response_id` (chunks, completion, superseded-by), attributes `tool_call_invocation`/`tool_call_result` to the latest requested id, flags `wrong_response_id` chunks (api-notes.md:46) and a `config` that is not the first frame (api-notes.md:23).
- **Scenario runner** (`src/bench/scenario.ts`, `runner.ts`): a scenario is `turns[]` + `expect`. A user turn sends `update_only` (`turntaking: "user_turn"`), then `update_only` with `turntaking: "agent_turn"` (api-notes.md:35: present "right before agent is about to speak"), then `response_required` with the next id and waits for `content_complete: true` or `turn_timeout_ms`. An `interrupt` on a turn appends whatever the agent already streamed under the open id to the transcript (it was spoken), then sends, `after_ms` later, another `update_only` with more user speech, the `agent_turn` update, and a new `response_required` with the next id, so the earlier id is superseded (api-notes.md:7, 36). A reminder turn sends `reminder_required`. After each completed turn the agent's text is appended to the transcript and sent as `update_only`.
- **Metrics** (`metrics.ts`, pure): time to first sentence = first `response` chunk after which the accumulated content ends in `.`, `!` or `?` (or the first chunk if the response is one chunk / `content_complete`), measured from the `response_required` send (api-notes.md:93); nearest-rank P50/P90 pooled across runs.
- **Scoring** (`scoring.ts`, pure): per run: `content_complete` received for every live (non-superseded) requested id; tool calls missing (expected name + argument subset never invoked), unnecessary (name in `forbidden_tools` or not among expected names), args-mismatch (`tool_args_mismatch`: expected name but arguments matching no expected entry, e.g. the pre-interrupt slot booked; informational, listed under the table, never a column and never fails a scenario), duplicate (same name + same arguments, `message` excluded, more than once within one caller request, i.e. a turn and the turn that superseded it); a silent tool turn (a completed live turn with a `tool_call_invocation` but no non-empty spoken chunk, api-notes.md:97, 99); protocol violations; `must_complete`; optional `agent_text_contains` substring check; a cheap voice lint for markdown in `content` (api-notes.md:102). Stale chunks after a supersede are counted as information, not failure (api-notes.md:52, 96).
- **Report** (`diff.ts`, `report.ts`, `cli.ts`): aggregates runs per scenario into `ScenarioScore`, prints a padded-string table, writes JSON, and `results-md.ts` renders `docs/results.md` from that JSON. Each run also gets a **transcript diff**: a hand-written line-level LCS diff (`diff.ts`, about 20 lines, no dependency) of the scenario's `expect.agent_transcript` (reference wording per agent turn after the begin message) against what the server said; it is in the JSON and printed under the table in `docs/results.md`, and is informational, never a column or a finding, because model wording varies between runs (in interrupt scenarios the text streamed before the interruption is its own utterance, so it appears as one extra `+` line).
- **Fake server** (`src/server/fake.ts`): `ws` server; per `response_id` (or per regex on the last user utterance, or fallback) plays a scripted reply: raw frames verbatim, chunks with fixed delays, tool-call frames, optional completion, optional `end_call`; honors supersede by cancelling timers. Deterministic, so tests assert exact findings; timings are asserted as ranges.
- **Reference server** (`src/server/session.ts`, `claude.ts`, `booking.ts`, `tools.ts`): `session.ts` implements the protocol against an `LlmClient` interface so it is tested with a fake LLM; `claude.ts` is the only file that imports `@anthropic-ai/sdk` at runtime.

## Key decisions
| Decision | Rejected alternative | Why |
|---|---|---|
| Bench validates with zod and *mirrors* Retell's drop/fallback rules | throw on the first bad frame | The documented failure mode is silent (api-notes.md:10, 50); the bench must keep going and report |
| `session.ts` depends on an `LlmClient` interface; Claude behind it | call the SDK inside the socket handler | Reference server is fully tested with no key (brief: tests never need it) |
| Fake server scripted by `response_id` + regex matchers | a second LLM-free "smart" agent | Deterministic findings for tests; the smoke run still looks sensible |
| Duplicate = same name + args across a supersede group | any repeated tool name | Matches the documented trap exactly (api-notes.md:95) |
| Stream Claude text deltas straight to `response` chunks | buffer to sentence ends server-side | Retell assembles sentences itself (api-notes.md:93); forwarding keeps TTFS honest |
| Hand-parsed argv, padded-string table | commander / cli-table | api-notes.md:122 |
| ESM + `tsx`, `tsc --noEmit` for types, no build step | tsc build to dist | Fewer moving parts for a demo repo |
| Reference server sends no sampling parameters and `thinking: { type: 'disabled' }` | `temperature: 0` as in Retell's guide (api-notes.md:98) | Retell's guide recommends temperature 0 with tools for OpenAI models, but Sonnet 5 rejects non-default sampling parameters, so the reference server sends none; thinking off because the bench measures the server, not the model's reasoning latency, and `max_tokens: 300` then covers spoken text only |
| Hand-written 20-line LCS transcript diff | pin `diff` (jsdiff 8, `createTwoFilesPatch`) | One fewer unverified npm pin; the output is a unified-style diff either way |
| `npm run results` starts the reference server in-process | background `npm run server` + `npm run bench` | Three README commands work in one terminal; no PID files, no readiness wait, one log to grep for provider failures |
| Any `ping_pong` reply credits the oldest outstanding ping | require the echoed `timestamp` to match | api-notes.md:44 documents only that a reply with an integer `timestamp` is required |

## Global constraints (exact values)
- Node 22.23.2; TypeScript 5.9.3; tsx 4.20.6; @types/node 22.18.6; ws 8.18.3; @types/ws 8.18.1; zod 4.1.12; yaml 2.8.1; vitest 4.1.6; @anthropic-ai/sdk 0.110.0 (every pin re-verified by `npm view` in Task 1; substitution rule there, plus the rule that an SDK type name `tsc` rejects is looked up in the installed `messages.d.ts`). No diff library.
- Ports: reference server 3217, fake server 3218; bench default URL `ws://127.0.0.1:3217/llm-websocket`; tests use port 0.
- Keepalive: send every 2000 ms, reply expected within 5000 ms (test override 100 ms / 150–400 ms; timing tests use intervals of at least 100 ms, ±1 margins, and `fileParallelism: false`). Begin-message timeout 5000 ms. Default `turn_timeout_ms` 15000.
- Model id `claude-sonnet-5` (build-brief.md:19), `max_tokens: 300`, `thinking: { type: 'disabled' }`, no sampling parameters (Retell's guide recommends temperature 0 with tools for OpenAI models, but Sonnet 5 rejects non-default sampling parameters, so the reference server sends none). Key only from `ANTHROPIC_API_KEY`; `.env.local` never read, printed, or committed; the build checks only that the variable name exists (`grep -c '^ANTHROPIC_API_KEY=' .env.local`).
- Naming: package `retell-llm-bench`; call ids `bench-<scenario>-<run>-<hex>`; scenario names `^[a-z0-9-]+$`; results run = 3 runs per scenario.
- Voice text rule for the reference server: no markdown, no lists, no emoji (api-notes.md:102).

## Out of scope (and why)
- Retell account, hosted API, real phone/web call (brief: none). LLM-judge grading, latency-per-node budget, UI, `agent_interrupt`/`update_agent`/`metadata` senders (accepted by `response_type` when received, never emitted, fields not validated), more than two tools, reconnect simulation (api-notes.md:17), `transcript_with_tool_calls` playback. All named in the README's "what was left out".

## Risks
- Pinned versions may not exist on npm → Task 1 verifies and substitutes deterministically.
- `claude-sonnet-5` may be rejected by the API, or a request parameter may be → the results task greps the server log for `failed:` and HTTP 400/401/429/529, stops on any hit, deletes the partial results, records the log tail in TRACKER; no guessing, no table with holes.
- Reference server may fail judgment scenarios (change-mind, clinical) → reported honestly; that is the point of the bench.
- Time: 16 tasks = 13.9 h + ~0.1 h worktree installs = 14.0 h (the round-1 plan printed 14.5 h for numbers that summed to 13.5 h); if over 2× budget, stop per build-brief.md:4.
- Timing tests on a loaded machine → intervals of at least 100 ms, ±1 margins on counts, `fileParallelism: false`.

## Not doing (bigger ideas, deliberately)
- Recording real Retell traffic and replaying it (needs an account).
- A `retell-llm-protocol` npm package extracted from `src/protocol` (ideas.md §5).
- An act-or-hold judgment set run through several models (ideas.md §3).
- Cut in plan review round 1 to stay inside the budget: (a) Task 12's by-hand no-key check via `tsx -e` (redundant with `scripts/results.ts`'s own exit-1 path, which Task 13 Step 5 exercises); (b) detailed field validation of `update_agent`, `metadata` and `agent_interrupt` (only `response_type` is checked; the bench never emits or scores them). Kept: the voice-markdown lint and all nine scenarios (the review's cuts (c) and (d) were not needed).
